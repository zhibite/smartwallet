# SmartWallet 聪明钱辅助工具 - 功能描述

> 项目定位：Solana 链手工收集的"聪明钱"钱包的辅助分析工具，为跟单系统提供精准信号与数据支撑。

---

## 1. 项目背景与目标

### 1.1 背景
当前团队在 Solana 链上维护一个跟单系统，依赖 "聪明钱"（Smart Money，即历史上具有稳定盈利能力的链上钱包）作为信号源。聪明钱名单通过手工收集与维护。

### 1.2 目标
围绕手工收集的聪明钱名单，构建一个数据采集 + 分析 + 展示的辅助工具，**为跟单系统提供高质量、可解释的跟单信号**。

### 1.3 规模定位
- 聪明钱数量：**50 个**（起步）
- 监控 Token：以活跃交易 Token 为主，规模随业务自然增长
- 数据保留：原始交易 1 年以上，时序数据可持续压缩归档

---

## 2. 核心概念

| 概念 | 定义 |
|---|---|
| **Smart Money** | 通过手工筛选的有盈利能力或领先性的链上钱包 |
| **Trade** | 一次链上成交（买入/卖出），基于解析后的 SPL Transfer + DEX 事件 |
| **Holding** | 某钱包在某个 Token 上的当前持仓 |
| **PnL** | 盈亏统计，包括已实现 / 未实现 / 时间加权 |
| **Token** | 链上代币，包含元数据、价格、市值、流动性、风险属性 |
| **Signal** | 由多个聪明钱行为汇聚出的可执行信号（如共识买入） |
| **Alert** | 信号的对外通知（Telegram / Webhook） |

## 3. 功能模块

### 3.1 聪明钱管理（Smart Money Management）

#### 3.1.1 基础管理
- 钱包地址的批量导入（CSV / JSON / 文本粘贴）
- 单条 / 批量编辑：标签、备注、来源、信任度
- 启用 / 禁用监控（下架后停止同步）
- 黑名单（与跟单系统解耦）

#### 3.1.2 标签体系
- **手工标签**：蓝筹猎手、土狗专捡、短线王、早鸟型、追涨型、砸盘型、KOL 等
- **系统标签**（自动推导）：
  - 短线王：平均持仓 < 6h 且胜率 > 60%
  - 土狗专捡：买入 Token 中上线 < 24h 占比 > 70%
  - 蓝筹持有者：平均买入金额 > 100k USD 且持仓数 < 5
  - 早期投资者：买入时间在 Token 首发 24h 内的占比 > 50%
  - 等
- 支持标签组合筛选

#### 3.1.3 评分与排序
- 按胜率、ROI、近 30 天表现、平均持仓时长、资金规模等维度排序
- 自定义权重评分公式（管理员可调）

---

### 3.2 交易历史采集（Transaction Sync）

#### 3.2.1 链上数据同步
- 主源：**Helius**（Enhanced Transactions + DAS API）
- 备份源：Solana 公共 RPC
- 同步策略：
  - **首次全量**：拉取每个聪明钱历史 N 天（默认 30 天）的交易
  - **增量同步**：Cron 每 30s 拉取新签名
  - **实时推送**：WebSocket 订阅钱包地址

#### 3.2.2 交易解析
- 识别 Raydium / Orca / Jupiter / Pump.fun / Meteora 等 DEX 的买卖事件
- 提取：方向、数量、单价、对手方、Gas、滑点
- 去噪：
  - 过滤内部转账（钱包之间互转不算交易）
  - 过滤失败交易
  - 过滤同一 Slot 内的 MEV / 夹子行为痕迹

#### 3.2.3 数据质量
- 多源价格校验（Helius / Birdeye / Jupiter 交叉对比）
- 异常交易标记（人工复核）
- 缺漏补全（自动重试 + 手动触发）

---

### 3.3 Token 数据采集（Token Metadata & Snapshot）

#### 3.3.1 Token 元数据
- 基础信息：合约地址、Symbol、Name、Decimals、Logo、官网、社交链接
- 项目方：部署者地址、是否开源 Mint、是否 Renounce
- 首发信息：首发平台、首发时间

#### 3.3.2 实时价格与市值
- 当前价、5m / 1h / 24h / 7d / 30d 涨幅
- Market Cap、FDV、流通量、Total Supply
- ATH 与距 ATH 回撤

#### 3.3.3 流动性
- 主池流动性、LP 锁仓量、池子创建时间
- 是否销毁 LP、是否锁仓

#### 3.3.4 筹码分布
- 持币地址数、Top10 集中度、巨鲸数量
- **聪明钱持币数**（核心指标）

#### 3.3.5 风险标记
- 是否 Honeypot、税率、是否 Rug 标记
- 多源风险数据库交叉验证（Birdeye / GoPlus / RugCheck）

#### 3.3.6 时序快照
- 价格 / 市值 / 流动性 / 持币数 定时快照（5min 一次）
- 历史 K 线聚合（5min / 1h / 1d）

---

### 3.4 盈利统计（PnL Analytics）

#### 3.4.1 成本算法
- 默认 **FIFO**（先进先出，与链上传统认知一致）
- 可选 **加权平均**（用于切换对比）

#### 3.4.2 盈亏维度
- **已实现盈亏**：卖出价 - 买入价 × 数量
- **未实现盈亏**：(当前价 - 均价) × 持仓数量
- **ROI**：单 Token ROI / 综合 ROI / 时间加权 ROI
- **收益曲线**：按日 / 周 / 月聚合

#### 3.4.3 排行指标
- 单笔最大盈利、单笔最大亏损
- 平均盈利、平均亏损、盈亏比
- 最大回撤、夏普比率
- 胜率（盈利笔数 / 总笔数）

#### 3.4.4 复盘视图
- 收益时间轴（带买卖点标注）
- 持仓周期分布
- 不同持仓时长下的胜率分布

---

### 3.5 协同信号（Cross-Wallet Signal）

#### 3.5.1 共识信号
- 多聪明钱**同一时间窗口**共同买入同一 Token
- 阈值可配置：人数 K、金额 M、时间窗口 T
- 排序维度：人数、金额密度、时间紧迫度

#### 3.5.2 行为模式
- 谁先买、谁后买、间隔多久
- 集体清仓检测
- 集体加减仓行为

#### 3.5.3 信号标签
- **共识买入**：≥ K 个聪明钱在 T 小时内共同买入
- **巨鲸异动**：单笔金额 > 阈值的买入
- **新币首吃**：Token 上线 24h 内聪明钱首次买入
- **集体出货**：≥ K 个聪明钱在 T 小时内卖出

---

### 3.6 实时监控与告警（Alert & Notification）

#### 3.6.1 告警类型
- 新买入实时推送
- 大额买入阈值告警
- 聪明钱集体行动告警
- 持仓清仓告警
- 价格异动 + 聪明钱仓位联动告警

#### 3.6.2 通知渠道
- **Telegram Bot**（推荐）
- **Webhook**（对接跟单系统）
- **站内消息**（前端）
- 邮件（可选）

#### 3.6.3 告警规则
- 全局规则 + 单钱包规则
- 时间窗口过滤（避免凌晨打扰）
- 静默期（同一信号短时间内不重复推送）

---

### 3.7 筛选取数（Query Builder）

#### 3.7.1 聪明钱筛选
- 维度：胜率、ROI、持仓时长、资金量、标签、行为特征
- 时间窗口：最近 24h / 7d / 30d / 自定义
- 支持 **交集**（多个条件 AND）和 **并集**（OR）

#### 3.7.2 Token 筛选
- 维度：被聪明钱持有数、涨幅、市值、流动性、上线天数、风险评分
- 排序：聪明钱集中度、近期共识强度、流动性深度

#### 3.7.3 协同筛选
- 被 ≥ N 个聪明钱同时持有的 Token
- 最近 T 小时内被 ≥ N 个聪明钱新买入的 Token
- 集体出货预警清单

#### 3.7.4 保存查询
- 常用筛选条件保存为"工作流"
- 一键运行历史回看

---

### 3.8 跟单信号输出（Follow Signal Export）

#### 3.8.1 跟单白名单
- 基于共识信号自动生成跟单 Token 列表
- 输出格式：JSON / CSV / API
- 包含：Token mint、共识强度、聪明钱列表、建议仓位

#### 3.8.2 仓位建议
- 基于资金量、风险等级、共识强度
- 持仓时长建议（基于聪明钱平均持仓时间）
- 止盈止损建议（基于聪明钱平均盈亏比）

#### 3.8.3 跟单系统对接
- HTTP Webhook 推送
- Kafka / Redis Stream 实时队列
- 共享数据库（跟单系统直接订阅 `signals` 表）

### 3.10 报告与复盘（Reports）

#### 3.10.1 定期报告
- 周报 / 月报自动生成（HTML / PDF）
- 涵盖：聪明钱整体表现、共识信号回顾、Top 标的、Top 聪明钱

#### 3.10.2 单兵报告
- 单个聪明钱战绩报告（可导出为 PDF）
- 单个 Token 复盘报告（聪明钱参与情况 + 价格走势）

#### 3.10.3 异常审计
- 异常交易行为审计
- 信号失效分析（哪些信号最终亏损）

### 3.11 标签智能化（Tag Engine）

#### 3.11.1 规则引擎
- 基于规则的自动标签（见 3.1.2）

#### 3.11.2 行为画像

## 4. 非功能性需求

### 4.1 性能
- 交易同步延迟：< 30s（实时推送 < 5s）
- 看板查询响应：< 1s
- 历史回溯：30 天 50 钱包 < 30 分钟

### 4.2 可靠性
- Worker 任务失败自动重试
- 多 RPC 节点自动切换
- 数据库每日备份

### 4.3 可扩展性
- 50 钱包起步，架构支持平滑扩展到 500+ 钱包
- 监控 Token 数量动态调整

### 4.4 数据安全
- 敏感配置（API Key）走环境变量
- 数据库访问权限最小化
- 操作审计日志

## 5. 数据规模估算（50 钱包）

| 数据项 | 年增量 | 三年累计 |
|---|---|---|
| 交易明细 | ~75 MB | ~230 MB |
| Token 快照（压缩后） | ~2 GB | ~5 GB |
| 元数据 / 持仓 / 信号 | < 50 MB | < 150 MB |
| **合计** | **~2 GB** | **~6 GB** |

→ 500 GB SSD 即可支撑 5 年+运行。

| 场景 | 对接方式 |
|---|---|
| 实时共识信号 | Webhook / Redis Stream |

## 7. 技术栈概览

- **前后端**：Next.js 15（App Router）+ TypeScript
- **数据库**：PostgreSQL 16 + TimescaleDB
- **缓存/队列**：Redis 7 + BullMQ
- **链上数据**：Helius（主）+ 公共 RPC（备）
- **Token 数据**：DexScreener / Birdeye / Jupiter
- **UI**：shadcn/ui + TailwindCSS + Recharts + TanStack Table
- **部署**：Docker Compose（单服务器起步）

详细技术方案见 [architecture.md](./architecture.md)。
